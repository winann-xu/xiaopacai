# ADR 0019：换绑必须先在原家长端解绑（TASK-REBIND-GATE）

- 日期：2026-08-24
- 状态：已实施并上线（Web v1.3.1 / Android v1.3.4）
- 相关：ADR 0009（账号体系）、V3 需求 11（解绑/换绑必须家长密码验证）

## 背景

真机复现（生产库 8.217.165.122 审计实锤）：儿童端绑定家长 A 后，扫家长 B 的
二维码即可“无障碍”换绑到 B；旧绑定 3ba70a6d（queen_zhou）与 9d86b673
（xwag14）之间无任何 `device.unpair` 记录，旧绑定悬挂为 offline paired。

## 根因

1. 儿童端换绑入口只检查本地残留（`hasChildResidue`），确认「清空并继续绑定」后
   `wipeAll` 重置 `device_id`（D2 决策），服务端把新 `device_id` 当全新设备绑定，
   无法关联旧绑定；
2. 服务端握手对已配对设备刻意忽略配对码、仅按证书指纹放行（防 117 断线重连雪崩），
   扫码握手必然成功，两道防线都缺“先查绑定状态”。

## 决策

- 儿童端扫码/手动配对入口统一先查 `GET /api/pairing/status`（当前 `device_id` +
  账号 JWT）：`bound=true` 弹「无法重新绑定」拦截，必须先由原家长端解绑
  （解绑为硬删除，行消失后 `bound=false` 才可重绑）；未绑定走原残留确认流程；
  未登录/网络异常/查询失败一律拦截，杜绝绕过归属纪律。
- 服务端第二道防线：P2P 握手对已配对设备携带**他人账号签发的 pending 配对码**
  确定性拒绝 `device_owned_by_other`（不计数限速）；不携码/同账号码仍按证书指纹
  放行，断线重连不受影响。
- `/api/pairing/verify` 在 `device_id` 已存在且归属他人时拒绝 403；归属本人/
  无归属时复用已有设备行，避免唯一索引冲突。
- 绑定状态接口的 `ownerAccount` 仅对归属账号本人或 admin 返回，防跨账号泄露。

## 影响与边界

- 正常首次绑定不变；解绑后重绑不变（服务端行已删除）。
- 断线重连不携码或携同账号码仍放行，117 场景回归测试保留。
- 儿童端未登录时换绑被拦截，需先以家长账号登录（门禁），属预期安全行为。
