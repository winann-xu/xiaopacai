# 小趴菜儿童端 OEM 保活说明

> [TASK-D1-02] 本文档说明小趴菜在各大 Android 厂商 ROM 上的后台保活策略与已知限制。

## 一、问题背景

Android 系统为了省电，会在后台限制或杀死长时间运行的第三方应用。
小趴菜需要后台持续运行以采集使用时长和执行超时停用，因此需要多层次的保活策略。

## 二、通用保活措施（已实现）

| 措施 | 说明 | 效果 |
|------|------|------|
| 前台服务 | Android 前台服务 + 持久通知 | 优先级最高，被杀概率最低 |
| START_STICKY | 服务被杀后系统自动重启 | 崩溃后自动恢复 |
| 开机广播 | 设备重启后自动启动服务 | 覆盖重启场景 |
| 电池优化豁免 | 请求忽略电池优化 | 减少 Doze 模式限制 |

## 三、各厂商特殊适配

### 3.1 华为 (Huawei/Honor)

- **限制**：锁屏后自动清理后台，前台服务可能被强制停止
- **用户操作**：
  1. 手机管家 → 启动管理 → 小趴菜 → 手动管理（允许自启动、关联启动、后台活动）
  2. 设置 → 电池 → 启动管理 → 同上
  3. 多任务卡片 → 下拉锁定

### 3.2 小米 (Xiaomi/Redmi/POCO)

- **限制**：MIUI 有严格的后台限制，"神隐模式"下前台服务可能被休眠
- **用户操作**：
  1. 安全中心 → 应用管理 → 权限 → 自启动管理 → 开启小趴菜
  2. 设置 → 电池与性能 → 应用智能省电 → 小趴菜 → 无限制
  3. 多任务 → 长按小趴菜卡片 → 加锁

### 3.3 OPPO (ColorOS)

- **限制**：ColorOS 有"智能省电"可能暂停后台应用网络权限
- **用户操作**：
  1. 设置 → 电池 → 应用耗电管理 → 小趴菜 → 允许后台运行
  2. 手机管家 → 权限隐私 → 自启动管理 → 开启
  3. 多任务 → 下拉锁定

### 3.4 vivo (Funtouch OS / OriginOS)

- **限制**：iManager 可能在后台清理时关闭通知，导致前台服务降级
- **用户操作**：
  1. i管家 → 应用管理 → 权限管理 → 自启动 → 开启
  2. 设置 → 电池 → 后台高耗电 → 允许
  3. 多任务 → 锁定

### 3.5 三星 (Samsung One UI)

- **限制**：较为宽松，但"优化电池使用量"可能影响前台服务
- **用户操作**：
  1. 设置 → 应用程序 → 小趴菜 → 电池 → 无限制
  2. 设备维护 → 电池 → 未监视的应用 → 添加小趴菜

### 3.6 原生 Android (Pixel / 类原生 ROM)

- **限制**：Doze 模式 + App Standby（Android 6.0+）
- **现状**：前台服务 + 电池优化豁免基本可稳定运行，保活效果最好

## 四、能力边界（必须如实告知用户）

⚠️ **以下为 Android 平台客观限制，非软件缺陷：**

1. **无法 100% 保活**：任何第三方应用都无法保证在所有 OEM 上持久存活
2. **安全模式绕过**：儿童重启设备进入安全模式后，所有第三方服务不启动
3. **OEM 强杀**：部分厂商（华为/小米）在极端省电模式下仍可能杀死前台服务
4. **Android 版本差异**：Android 12+ 对前台服务的限制更严格
5. **物理关机**：设备关机后无法执行任何超时停用

**缓解措施**：
- 提供详细的 OEM 配置引导（本文档）
- 家长与儿童建立信任关系，软件为辅助工具
- 发现绕过行为时，通过已缓存的本地策略在下一次启动时执行

## 四·补 [TASK-MILESTONE-V3] 需求 5：上滑结束 / 强制停止专项说明

真机 Bug「上滑结束小趴菜后管控失效」修复后的行为与剩余边界：

| 场景 | 行为 | 恢复时限 |
|------|------|----------|
| 最近任务上滑结束（进程被杀） | onTaskRemoved 抢先注册 5 秒系统侧恢复闹钟（不随进程消亡）；拉起后立即重放采集重新执行拦截，并通知「守护已自动恢复，管控重新生效」 | 约 5~30 秒 |
| OEM 后台杀 / 异常杀 | 服务重启时按心跳间隔检测（>5 分钟无心跳且非重启）→ 通知家长；管控生效中则立即重放 | 取决于 OEM，检测后立即 |
| 设置 → 强制停止 | **系统会一并取消全部闹钟与 WorkManager，无法自我恢复**；只能等用户重新打开应用，打开即恢复并通知 | 用户操作决定 |
| 无障碍服务被系统移除 | 分钟级自检 + 安全通知带「去开启无障碍」快捷按钮 | ≤ 1 分钟检测 |

**技术要点**：

- GuardianAlarmReceiver 此前未在 AndroidManifest 声明，AlarmManager 兜底链路实际静默失效；
  V3 已补声明（exported=false），30 分钟兜底闹钟恢复生效；
- 心跳每分钟打标 `guardian_heartbeat_ms` + 开机时刻 `guardian_boot_epoch`（区分重启与被杀，防误报）；
- 管控生效打标 `enforcement_active`（TimeoutExecutor 写入），恢复链路据此选择快速重放与通知文案；
- 三重守护现状：前台服务 START_STICKY + WorkManager 15 分钟 + AlarmManager 30 分钟，
  上滑恢复闹钟为第四条系统侧通道（5 秒）。

**如实结论**：第三方应用无法绝对阻止孩子手动结束进程。以上措施将「管控失效窗口」
从“永久（直到家长发现）”压缩到秒级~分钟级，并在每次恢复时通知家长（安全频道通知），
这是 Android 平台约束下的可行上限。

## 五、引导流程建议

应用首次启动时展示以下引导：

1. 权限引导页（内置）→ 完成各系统权限设置
2. OEM 保活引导 → 根据设备品牌跳转到对应设置页
3. 提示用户将本说明转发给家长，协助完成配置
