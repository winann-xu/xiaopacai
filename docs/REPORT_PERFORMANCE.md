# 小趴菜性能与耗能评估报告

版本：V1.0    日期：2026-08-11    评估：Codex@50.20    范围：Android 儿童端常驻链路

## 1. 结论

整体为**轻量级**设计：单前台服务 + 无障碍 + 2 个定时器 + 1 个心跳；无第三方 SDK 广告/统计/推送 SDK。估算空闲耗电占比 <1%/天（见 §4）。存在可落地的低风险优化点（§5），已列入优化清单。

## 2. 运行负载现状

| 模块 | 频率 | 单次开销 | 说明 |
|------|------|---------|------|
| UsageStatsCollector | 每 5 分钟 | 查询 UsageStats + SQLCipher 批量 upsert | 数据量：每日约 20~40 条应用记录 |
| P2P 心跳 | 每 30 秒 | 1 条 JSON 帧（~100B） | 保持连接；断线时指数退避重连 |
| AntiBypassService | 每 60 秒 | Settings/AppOps/PM 查询 | 3 次系统查询 + 条件通知 |
| 前台服务 | 常驻 | 通知 + 服务进程 | Android 前台服务强制 |
| 无障碍服务 | 常驻 | 仅超时/公告时活跃 | 空闲时基本零开销 |

## 3. 量化估算

- 唤醒次数：采集 288 次/天 + 心跳 2880 次/天（30s）+ 防绕过 1440 次/天（60s）≈ **4600 次/天**。
- 网络流量：心跳 ~100B × 2880 ≈ 288KB/天；上报 ~5KB/次 × 12 ≈ 60KB/天；合计 **< 400KB/天**。
- 数据库写入：5 分钟批次写 ≤ 200 行/天；SQLCipher 加密写开销可忽略（本地）。
- 内存：常驻进程基线约 40~60MB（Compose + SQLCipher），符合轻量定位。
- 电量：按每次短唤醒 5ms CPU 估算，日活跃时长 < 30s CPU，耗电占比可忽略；主要耗电来自系统级（屏幕/网络待机）。

## 4. 风险点

1. 30s 心跳在弱网/蜂窝下会产生无效唤醒与电量损耗（可动态化）。
2. 5 分钟采集若赶上系统 Doze 会延迟（不影响正确性）。
3. 每 60 秒 PackageManager/Settings 查询在低端机有轻微 CPU 开销。
4. SQLCipher 每次操作开连接（`db.close()` 后重开），有连接建立开销。

## 5. 优化建议（低风险，已列入提示词包）

| 优先级 | 优化 | 预期收益 |
|-------|------|---------|
| 高 | 心跳动态化：连接稳定后 30s→60s；丢包回退 15s | 心跳流量/唤醒减半 |
| 中 | AntiBypass 检查 60s→120s，仅状态变化时发通知 | 系统查询减半 |
| 中 | 同一应用同日 upsert 合并为一次写 | DB 写次数下降 60% |
| 低 | 连接池化/复用 SQLCipher 连接（批量事务已有） | 连接建立开销下降 |
| 低 | 采集与 WorkManager 对齐 Doze 窗口 | 弱网下电量更优 |

## 6. 结论

小趴菜符合轻量级定位，无重型依赖；按 §5 落地后可进一步降低 30~50% 的定时唤醒开销。优化属于低风险改动，已纳入需求 8 实施范围，回归后更新本报告。
