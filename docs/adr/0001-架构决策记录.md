# ADR-0001：小趴菜项目架构决策记录模板

- **状态**：已采纳
- **日期**：2026-08-10
- **决策者**：Claude@50.53（主开发）

## 背景

小趴菜（儿童守护 · 家长监控软件）的架构设计需要在以下约束下进行：
1. 数据不上云，仅存终端设备
2. P2P 局域网直连通信
3. 开源免费（Apache-2.0），无闭源组件依赖
4. 三天冲刺交付成品级软件

## 决策

采用以下架构方案：

### 整体架构：C/S + P2P 混合模式

- **儿童端 (Android)**：Kotlin + Jetpack Compose，作为数据采集端
- **家长端 (Windows)**：C# / .NET 8 + WPF，作为管理与数据中心
- **通信层**：独立 P2P 模块（mDNS 发现 + TCP/TLS 1.3 直连）

### 关键技术选型

| 决策点 | 选择 | 理由 |
|--------|------|------|
| Android UI | Jetpack Compose | 声明式 UI，代码量少，适合快速开发 |
| Windows UI | WPF (.NET 8) | 成熟稳定，Windows 原生支持好 |
| 数据库加密 | SQLCipher (社区版) | BSD 许可，与 Apache-2.0 兼容 |
| 网络发现 | mDNS/DNS-SD | 零配置局域网服务发现 |
| 安全传输 | TLS 1.3 + 双向证书认证 | 行业标准，防中间人攻击 |
| 配对机制 | 一次性配对码 + 二维码 | 用户友好，安全性可接受 |
| 构建工具 (Android) | Gradle + Kotlin DSL | Android 官方标准 |

## 后果

### 优势
- 完全离线可用，不依赖云端服务
- P2P 架构天然保护用户隐私
- 开源许可与依赖完全兼容

### 风险
- Android 端超时停用依赖无障碍服务，能力受限于平台
- P2P 网络受家庭网络环境影响（如路由器不支持 mDNS）
- 家长端仅 Windows，macOS 家长无法使用（后续可扩展）

### 缓解措施
- 提供手动 IP 配对兜底方案
- 文档如实说明超时停用的平台能力边界
- 架构预留跨平台扩展点
