# ADR-0002：P2P 通信协议设计决策

- **状态**：已采纳
- **日期**：2026-08-10
- **决策者**：Claude@50.53（主开发）

## 背景

小趴菜需要在家长端（Windows）与儿童端（Android）之间建立安全、可靠的点对点连接。由于不依赖云端服务，所有通信必须在家庭局域网内通过直连方式完成。

## 问题

1. 如何在无配置的情况下自动发现对方设备？
2. 如何保证连接安全（防中间人攻击）？
3. 如何处理网络不稳定导致的断线？
4. 如何在纯局域网环境下完成端到端身份认证？

## 决策

### 1. 发现机制：mDNS/DNS-SD 为主，UDP 广播为兜底

- **选择 mDNS/DNS-SD**：零配置局域网服务发现标准，能提供结构化服务信息（IP + Port + TXT 记录）
- **UDP 广播兜底**：部分路由器/网络环境不支持 mDNS，UDP 广播作为降级方案
- **手动 IP 输入**：极端情况下最后的手段

### 2. 安全连接：TLS 1.3 + 证书指纹固定

- **选择 TLS 1.3**：最新标准，握手效率高（1-RTT），加密强度足够
- **不使用预共享证书 CA**：因为没有中心化基础设施
- **采用自签名证书 + 指纹固定（Certificate Pinning）**：首次配对记录证书 SHA-256 指纹，后续连接比对该指纹
- **理由**：本地网络环境下，证书固定的安全等级等同于 CA 验证，且无需外部依赖

### 3. 配对认证：一次性配对码 + 二维码

- **原因**：局域网内可能存在多台同名设备，用户需要一种方式确认正在连接的是自己的设备
- **实现**：家长端生成 6 位随机配对码，通过二维码（或口述）传递给儿童端
- **理由**：简单可靠，符合"本地优先"设计，不需要任何外部服务

### 4. 断线重连：指数退避 + 增量同步

- **心跳机制**：每 30 秒一次，连续 3 次无响应视为断线
- **重连退避**：1s → 2s → 4s → 8s → 16s → 最大 60s
- **增量同步**：儿童端维护每条数据的同步状态，重连后按 sync_status 查询未同步数据

### 5. 消息帧协议：长度前缀 + JSON

- **使用 4 字节大端长度前缀 + JSON 消息体**
- **选择 JSON**：可读性好，调试方便，跨语言支持完善
- **不选用 Protobuf/FlatBuffers**：本项目数据量小（日均 <5MB），JSON 性能完全足够，且不需要额外编译步骤

## 替代方案与拒绝理由

| 替代方案 | 拒绝理由 |
|---------|---------|
| WebRTC | 需要 STUN 服务器（违反不上云约束）；信令通道需要外部服务 |
| MQTT | 需要 Broker（违反不上云约束）；与 P2P 直连架构冲突 |
| Bluetooth/BLE | Windows 桌面端 BLE 支持不完善；速率太低不适合数据同步 |
| HTTP + REST | 不适合双向实时通信；心跳维持复杂 |
| JWT + 外部认证 | 需要认证服务器（违反不上云约束） |

## 后果

### 优势
- 完全本地化，无外部依赖
- TLS 1.3 提供工业级加密保护
- 发现-配对-连接流程简单，用户友好
- 消息格式可扩展

### 风险
- mDNS 在某些企业网络中可能被屏蔽（UDP 广播兜底缓解）
- 自签名证书需要用户理解配对流程（文档与引导缓解）
- 首次配对需要家长与儿童在同一局域网内
- 证书过期（365天）需要重新配对

### 后续优化方向
- 支持 IPv6 链路本地地址（fe80::）发现
- 证书自动续期
- 连接质量自适应（RTT 探测 + 超时动态调整）
