# 小趴菜 · 信息安全基线（项目最底层要求）

> 版本：V1.0 ｜ 日期：2026-08-14 ｜ 适用范围：Web / Android / Windows / P2P 中继 / 部署 / 文档
>
> **优先级声明：安全 > 功能 > 性能。**
> 任何功能、修复、重构不得以关闭、绕过、弱化以下红线为代价。
> 若实现与红线冲突，必须先走安全评审并取得明确批准，禁止自行取舍。
> 违反任一红线的代码/配置 = P0 阻断项，禁止进入公网生产环境。

## 一、身份认证（Authentication）

- **R1.1** 除登录、扫码 ticket、重置密码、健康检查、静态资源、下载中心外，所有 Web API 必须鉴权（JWT Bearer）。
- **R1.2** JWT 签名密钥必须为 ≥32 字节的高强度随机值；生产密钥禁止写入代码、仓库、明文配置文件；
  必须通过环境变量/密钥管理系统注入；测试密钥与生产密钥严格隔离。
- **R1.3** 密码必须使用慢哈希（PBKDF2 / Argon2，带随机盐），禁止明文、MD5、SHA1、可逆加密存储；
  登录失败必须限流/退避；会话（access/refresh token）必须有有效期、可吊销、轮换机制。
- **R1.4** 扫码登录 ticket、重置密码 ticket 必须一次性、有时效、绑定客户端与用户，禁止重放。

## 二、授权与越权（Authorization）

- **R2.1** 所有按设备/账号访问的接口必须校验**资源归属**：
  家长只能操作自己账号下绑定的设备；管理员操作必须留痕。水平越权（换 ID 访问他人数据）= P0。
- **R2.2** P2P 消息必须校验 deviceId 与账号绑定关系；禁止仅凭 deviceId 即可冒充/接收他人数据。
- **R2.3** 中继路由必须按 owner 绑定关系转发，禁止跨账号路由；会话归属必须服务端验证。
- **R2.4** 管理端功能仅限 admin 角色；角色升级/降级必须有审计。

## 三、传输安全（TLS）

- **R3.1** 公网 Web 必须 HTTPS（TLS 1.2+），禁止明文 HTTP 承载登录与敏感接口；HSTS 开启。
- **R3.2** P2P 长连接必须 TLS，且**必须校验对端身份**（证书指纹固定/双向校验）。
  **禁止“接受任意客户端证书”**（当前 P2pListenerService 的
  `userCertificateValidationCallback => true` 属于违反项，必须修复）。
- **R3.3** 客户端必须校验服务端证书指纹（Android/Windows 已实现指纹比对的逻辑必须保持并定期审计）。

## 四、防爆破与滥用（Rate Limit / Abuse）

- **R4.1** 登录、注册、扫码 ticket、重置密码、配对码验证必须限流（IP+账号维度）与失败退避/锁定。
- **R4.2** 6 位数字配对码可暴力枚举（10^6），P2P 握手与配对接口必须限流、过期、一次性，并记录失败审计。
- **R4.3** API 必须限制请求体大小、频率、连接数；P2P 必须限制并发会话数与帧大小（现有 1MB 限制须保留并测试）。

## 五、输入与注入（Input / Injection）

- **R5.1** 所有外部输入必须白名单校验：
  时间必须 `HH:mm`、限额/分钟必须数值范围、包名必须合法格式、JSON 必须结构校验；
  拒绝未知字段或超范围值（当前 Web 端曾把就寝时间存成 ISO 时间戳 = 违反示例，已修复并纳入回归）。
- **R5.2** 禁止拼接 SQL；所有查询必须参数化（现有 DAO 参数化模式须保持并扩展到新增代码）。
- **R5.3** 禁止把用户输入拼入命令执行、动态类加载、反射目标；P2P 消息类型/负载必须白名单解析。
- **R5.4** 应用包名黑白名单匹配必须精确匹配，禁止子串/字符串包含式误判导致绕过或误伤。

## 六、数据与隐私（Data / Privacy）

- **R6.1** 儿童端本地数据库必须加密（SQLCipher），密钥不得明文落盘（KeyStore 优先）。
- **R6.2** 服务器不得存储明文密码、明文令牌、证书私钥；数据库文件必须加密。
- **R6.3** 隐私数据默认存用户手机端；服务器只保留“账号、必要互联信息、诊断/报告所需最小数据”。
  儿童使用明细属敏感数据，必须最小化、按需、可删除（账号解绑/注销时级联清理）。
- **R6.4** 诊断数据必须去标识化/最小化，禁止包含通讯录、短信、位置等与监护无关数据。
- **R6.5** 数据导出/下载必须鉴权+审计，导出文件不得包含密码、令牌、他人数据。

## 七、密钥与配置管理（Secrets）

- **R7.1** 生产密钥（JWT、DB、TLS 私钥）禁止进 Git、禁止明文进 appsettings；
  必须环境变量/密钥管理注入，密钥文件权限最小化（0600）。
- **R7.2** 默认口令（admin/admin123 等）必须首次登录强制改密，禁止公网保留默认口令。
- **R7.3** 密钥必须可轮换，轮换不得导致服务中断或数据不可读。

## 八、Web 前端安全（Frontend）

- **R8.1** 禁止把 access/refresh token 存 localStorage（XSS 可窃取）；
  优先 httpOnly+Secure+SameSite Cookie 或内存态+刷新机制，并配套 CSRF 防护。
- **R8.2** 必须启用 CSP、禁止内联危险脚本、输出编码；依赖必须锁版本并漏洞扫描（npm audit）。
- **R8.3** 敏感操作（改密、解绑、数据导出、策略变更）必须二次确认并审计。

## 九、日志与审计（Logging / Audit）

- **R9.1** 安全事件必须记录：登录成败、越权尝试、配对/解绑、策略变更、公告发布/撤回、数据导出、账号管理。
- **R9.2** 日志禁止包含密码、令牌、明文密钥、完整敏感数据；日志必须防篡改（追加式/只读/定期归档）。
- **R9.3** 审计日志必须可查询、可导出（仅管理员），保留期符合数据保留策略。

## 十、部署与运维加固（Hardening）

- **R10.1** 公网仅暴露必要端口（443/80，及受控的 P2P 端口）；服务以最小权限非 root 运行。
- **R10.2** 反向代理/网关开启：TLS 终止、请求体限制、限流、WAF（可选）、安全响应头。
- **R10.3** 备份必须加密，备份中不得含未加密密钥；恢复流程必须演练。
- **R10.4** 上线前必须执行依赖漏洞扫描与安全回归；监控告警（异常登录、异常流量、P2P 异常会话）必须生效。

## 十一、供应链与依赖（Supply Chain）

- **R11.1** 所有依赖锁定精确版本；定期执行：
  `npm audit`、`dotnet list package --vulnerable`、Android 依赖扫描（Gradle/OWASP dependency-check）。
- **R11.2** 已知高危漏洞依赖禁止上线；引入新依赖必须评审。

## 附：违反基线处理

- 违反 = P0 阻断项：禁止合并、禁止上线；先修复+回归+记录，再走发布流程。
- 所有测试（含 AI 测试提示词）必须逐条对照本基线，输出“红线合规勾选表”。
