# 小趴菜「强管制版」全面评估报告

> 评估方向：Android Enterprise 专用设备模式（方案二：DPC / Device Owner / Lock Task kiosk）
> 评估日期：2026-08-23 ｜ 评估人：Codex@50.20（主测试/集成角色）
> 评估方式：仅评估，未修改任何既有代码；结论基于项目仓库现状（xiaopacai android/docs、xiaopacai-web、安全基线、ADR 0016、DEVICE_OWNER.md）
> 修订 v1.1（用户方案约束，2026-08-23）：① 不涉及学校/教育机构，仅为家长与儿童间的应用；② 不收集真实姓名、身份证件信息；③ 不收集通讯录。

---

## 0. 执行摘要

**结论：强管制版技术可行，值得作为独立产品线立项推进；但它必须被界定为「家庭专用设备（学习平板/电视盒子）+ 家长统一管理（家庭多设备）」场景，不能作为现有家庭版（无障碍+前台服务）的替代品。**

- **四端可行性**：Android = 高（唯一主战场）；Android TV/盒子 = 中高（细分高价值）；iOS = 低（家庭 iPhone 不可行；家庭 iPad 仅手工监督高成本路径）；Windows = 低（仅家长端，不建议做儿童端强管制）。
- **两种 APP 版本**：儿童守护端（kiosk，可含 DPC 职责）与 家长管理端（家庭多设备）；Web 后端需做轻量家庭设备管理面，现有 P2P TLS 中继与账号体系可复用。
- **中国大陆适配**：无 GMS → 二维码/零触摸/NFC 批量预置基本不可用，主通道只剩 **ADB 预置** 与 **OEM 预装（家庭专用设备渠道）**；二维码仅对带 GMS 的设备有效；HarmonyOS NEXT 不兼容 APK，需要时须另做原生版。
- **合规**：必须对齐《未成年人网络保护条例》《移动互联网未成年人模式建设指南》《个人信息保护法》监护人同意与 App 备案；不采集真实姓名/证件/通讯录后敏感数据面大幅收窄，但透明告知、可退出、数据最小化仍是底线。
- **三大风险**：① 把「防绕过」宣传为「绝对锁定」→ 虚假宣传与投诉；② ROM 兼容事故（本项目在 OPPO 上已有前科）；③ 家长与儿童间的信任/合规风险（监护人同意留痕、儿童数据最小化）。

## 1. 方案定位与边界

### 1.1 强管制版定义

- 儿童设备 = **家庭专用设备**（家长购买并初始化的学习平板或电视盒子），非儿童已有的个人手机；管理方仅为家长，不涉及学校/教育机构。
- 架构 = 企业管理器/DPC → Device Owner → Lock Task kiosk → 儿童守护应用。
- 策略控制、应用白名单、设备限制由系统 DPM 执行；使用时长采集与报告仍由现有业务代码负责。
- 管控目标：儿童不拥有完整 Android 自由度，专注学习/白名单内容。

### 1.2 与既有决策的关系

- 与 [DEVICE_OWNER.md](../../android/docs/DEVICE_OWNER.md) 和 ADR-0016（Bug1-C）「只检测不激活、不引导 ADB」的衔接：**ADR 0018（2026-08-24，v1.3.0）已实施**「强管制模式」自授权预置通道——家长在受控入口内完成 Device Owner 预置，普通用户界面仍不出现 ADB/命令提示（延续 D4 决策）。

### 1.3 与三个方案的关系

| 方案 | 内核 | 定位 | 关系 |
|---|---|---|---|
| 方案三（现有家庭版） | 无障碍+前台服务 | 已有手机上的尽力防绕过 | 基线，保持不变 |
| 方案一（DO 加固） | DO + Lock Task | 现有设备可选加固层 | 可叠加在基线上 |
| 方案二（强管制版） | DDM 专用设备 | 家庭专用设备/家长多设备管理 | 本报告评估对象 |

## 2. 多端可行性评估

### 2.1 Android（手机/平板）—— 可行，主战场

| 维度 | 评估 |
|---|---|
| 预置通道 | ① ADB：`dpm set-device-owner`，需新设备/无账号+USB 调试，无 GMS 国产设备主通道；② QR/NFC/zero-touch：需 Google Play 服务，国内无 GMS 设备不可用；③ OEM 预装/厂商合作：家长专用设备出厂预装，需厂商合作（非学校渠道） |
| DPC 能力 | Lock Task（`setLockTaskPackages`/`startLockTask`/`setLockTaskFeatures`）、禁卸载、隐藏应用、用户限制（禁恢复出厂/禁装卸载/禁调试/禁加用户/禁改时间/禁网络配置）、禁截屏、禁状态栏、静默更新、用量访问免授权、安全日志 |
| 与产品功能映射 | 超时整机停用 = 动态进入/退出 Lock Task；部分停用 = 系统白名单动态维护；报告/公告/P2P = 复用现有业务代码 |
| 残余绕过向量 | 安全模式启动、Recovery 恢复出厂（多数 ROM 第三方 DO 无法拦截）、ADB/root/Xposed、多用户/分身（DO 可用用户限制缓解）、关机断网、时间篡改（DO 可强制自动时间+服务端时间审计）、第二台设备热点 |
| 机型问题 | 国产 ROM（ColorOS/HyperOS/MagicOS/OriginOS）行为差异大；OPPO/小米等对 `dpm` 命令有额外校验；内置儿童空间/学生模式与第三方 kiosk 功能重叠 |
| 结论 | **可行，MVP 主战场**。建议机型白名单策略：先支持 2–3 款学习平板/教育平板，再扩盒子 |

### 2.2 Android TV / 电视盒子 —— 中高可行，细分高价值

| 维度 | 评估 |
|---|---|
| 预置 | 国内电视盒子多为 AOSP 系、无 GMS，ADB 预置 DO 通常可行（当贝/小米盒子/天猫魔盒等）；部分盒子厂商锁 ADB，需实测 |
| 管控 | Lock Task 同样适用；系统自带「儿童模式/少儿模式」是主要竞争对手；需 leanback（DPAD 遥控）UI 适配 |
| 内容合规 | 纯 kiosk/桌面应用不构成播控平台；但若预置/白名单内置视频内容，内容服务本身需符合广电 OTT 播控与牌照要求，需法务确认 |
| 价值 | 「儿童看电视时长/内容管控」需求真实，且盒子成本低、易批量 |
| 结论 | **阶段 2 做**：先在 Android 平板跑通，再出 TV flavor（leanback + 遥控导航 + 电视 UI 走查） |

### 2.3 iOS / iPadOS —— 家庭 iPhone 不可行，家庭 iPad 仅高成本手工监督路径

| 维度 | 评估 |
|---|---|
| 消费者 iPhone | 第三方应用**无 kiosk/Device Owner 概念**；Screen Time/引导式访问（Guided Access）是苹果自带；FamilyControls 框架需苹果单独审批且极少对第三方开放 → 家庭 iPhone 强管制**不可行** |
| 家庭 iPad（可选） | 唯一可行路径 = 家长用 Mac + Apple Configurator 2 手工监督 + Single App Mode；不涉及学校/机构（ABM/DEP 需组织资质，不在本方案范围） |
| 成本 | 需要 Mac 工具链；无 MDM 订阅但操作门槛高，比 Android 高一个量级 |
| App Store | 设备管理类权限/能力在消费者分发场景会被拒审；监督设备不走公开商店分发 |
| 结论 | **默认不做**；优先级最低，仅作长期可选项 |

### 2.4 Windows —— 不建议做儿童端强管制

| 维度 | 评估 |
|---|---|
| 平台能力 | 无 DDM 对应物；kiosk 需 Assigned Access（Win 10/11 Pro/Enterprise，家庭版无）、MDM（Intune/ConfigMgr）或第三方 kiosk 软件；第三方儿童端普遍面临 UAC、杀软、反作弊冲突 |
| 家庭场景 | 微软家庭安全（Microsoft Family Safety）是主流；第三方强管制收益低、维护高 |
| 项目现状 | 现有 Windows 应用是**家长端**（报告查看/P2P 中继），继续保留此定位 |
| 结论 | **不做 Windows 儿童端**；可为「家庭共用电脑」场景提供 Assigned Access 部署指引文档（低投入） |

### 2.5 国产操作系统

- **HarmonyOS NEXT（纯血鸿蒙）不兼容 APK**：若目标市场覆盖鸿蒙手机/平板，需原生开发，工作量独立于 Android 线，建议暂缓、阶段 3 再评估。
- **AOSP 系（ColorOS/HyperOS/MagicOS/OriginOS）**：APK 兼容，但锁任务/保活/预置行为差异大，必须机型矩阵测试。

## 3. 两种 APP 版本与 Web 后端适配

### 3.1 版本界定（两种 APP 的说明）

本报告的「两种 APP 版本」指强管制产品线内的两个端；同时说明它们与现有家庭版的关系（同一仓库、双 flavor/双 APK）。

| 端 | 运行位置 | 核心职责 | 新增 | 复用 |
|---|---|---|---|---|
| 儿童守护端（kiosk） | 儿童专用平板/盒子 | 超时停用、白名单内应用、报告采集、公告、P2P | DPC 职责（或伴生 DPC 包）、Lock Task 生命周期、DO 策略中心、静默更新、逃生舱、预置状态上报 | UsageStatsCollector、TimeoutExecutor、报告、公告、P2P/SyncManager、SQLCipher |
| 家长管理端 | 家长手机（现有家长端改造） | 家庭多设备列表、策略调整、远程命令、报告、公告 | 多设备/分组（多娃家庭）、命令下发（立即锁定/解锁/重启/擦除/解除 DO） | 现有账号体系（邮箱+JWT）、P2P、云端同步 |
| Web 家长控制台（轻量管理面） | 服务器 | 设备台账、策略版本、报告、导出 | 新增家庭设备管理面 | 现有 admin 体系、下载中心、审计日志 |

**工程形态建议**：单代码库 + Gradle 双 flavor（`family` 保持现状、`strict` 输出 dpc+kiosk 两个包），同签名保证升级兼容；避免拆两个仓库带来的双份维护。

### 3.2 儿童守护端设计要点

1. **DPC 与 kiosk 是否同包**：推荐同包（一个 APK 既是 DO 又是 kiosk 应用），省去双包签名/更新/联调复杂度；若未来接 OEM/第三方 DPC 生态再拆分。
2. **Lock Task 生命周期**：不做常驻 kiosk；超时/就寝触发时进入、解除/家长解锁时退出（白名单随策略动态维护），保住「超时停用+每日重置」产品语义。
3. **逃生舱（P0）**：应用内「家长身份验证 → `clearDeviceOwnerApp`/`stopLockTask`」受控退出；必须设计，否则设备可能永久锁死。
4. **静默更新（P0）**：DO 经 PackageInstaller（`setRequireUserAction(false)`）静默升级；需在目标 ROM 实测，失败时降级为下载中心手动装。
5. **策略重放**：开机/更新/DO 激活后重放全部 DPM 策略（复用 BootReceiver/onEnabled 回调）。
6. **角色锁定**：DO 设备上禁止切到家长角色，儿童无法用家长入口绕过。

### 3.3 Web 后端适配（轻量家庭设备管理面）

| 模块 | 现状 | 强管制版改造 |
|---|---|---|
| 账号/家庭 | 邮箱账号+JWT，admin 体系 | 以家长账号为管理主体，支持一个家庭多设备/多娃分组；平台 admin 仅运维，不做组织/教师角色 |
| 设备台账 | devices 表（owner/online/健康度） | 增加预置状态、策略版本、DO 状态、固件/APK 版本、归属家长账号与分组（多娃）、最后在线 |
| 预置与认领 | 配对码+二维码绑定 | 生成预置 QR/令牌（DPC 包名+APK 下载 URL+org+policy+指纹）；设备 claim、unenroll、重新预置 |
| 策略引擎 | 单设备策略推送（P2P） | 版本化策略、分组下发、下发回执、单调版本号冲突解决（拒绝旧版本覆盖） |
| 远程命令 | 公告/策略下行 | 命令队列：立即锁定/解锁/重启/擦除/静默更新/解除 DO；幂等+离线缓存 |
| 通道 | P2P TLS 中继长连接（:9527） | 保留；新增 HTTP(S) 轮询兜底（P2P 掉线时拉取策略/命令），设备认证沿用 deviceId+证书指纹+会话令牌 |
| 报告 | 周期使用报告、日志 | 按儿童/设备聚合（多娃家庭）、导出（Excel/PDF）、保留期与删除（对齐 PIPL） |
| 合规留痕 | 审计日志部分 | 监护人同意记录（时间戳+版本）、家长操作审计；无学校/机构授权场景 |
| 数据层 | SQLCipher SQLite | 家庭规模（数台–数十台）SQLCipher SQLite 完全足够；保留迁移评估即可 |
| 下载中心 | 3 ABI Release APK | 双 APK 多 ABI + 更新清单；同签名升级 |
| 安全基线 | SEC-K3 限速、越权防护等 | 全量适用；新增设备命令鉴权（防跨账号越权下发）、命令操作审计 |

## 4. 优缺点对比

### 4.1 强管制版 vs 现有家庭版 vs DO 加固版

| 维度 | 强管制版（方案二） | 家庭版（方案三） | DO 加固版（方案一） |
|---|---|---|---|
| 管控强度 | 系统级（最高） | 应用级（尽力） | 系统级但仅限已激活设备 |
| 适用设备 | 家庭专用平板/盒子 | 任何已有手机 | 满足预置条件的设备 |
| 部署门槛 | 中-高（家长完成一次预置） | 低（装 APK+授权） | 中（ADB/新设备条件） |
| 防绕过能力 | 高（DO+Lock Task） | 低-中（可被关闭权限/强停/安全模式绕过） | 中-高 |
| 开发成本 | 高（DPC+策略+后端管理面+多端） | 低（增量收尾） | 中 |
| 维护成本 | 高（机型矩阵/售后/合规） | 中（多 ROM 保活） | 中 |
| 合规难度 | 中（未成年人模式/监护人同意/App 备案） | 中（敏感权限明示） | 中-高 |
| 隐私争议 | 中-高（家长-儿童信任敏感） | 中 | 高 |
| 商业模式 | 家庭订阅/一次性授权/专用设备套装；开源免费双轨 | 免费开源（现状） | 中间态 |
| 竞品壁垒 | 中-高（OEM 预装/家庭服务深度） | 低（同质化） | 中 |
| 主要失败风险 | ROM 兼容、合规、售后 | 被绕过、被替代 | 预置条件苛刻 |

### 4.2 结论

- **三轨共存**：家庭版是基线（继续收尾加固）；DO 加固是可选项；强管制版是独立产品线。
- 强管制版换来的「最强管控」对应「最高成本与合规责任」，必须用家庭专用设备场景消化，不能泛化到家庭已有手机。

## 5. 技术路线、中国大陆适配与合规

### 5.1 技术路线（分阶段）

**阶段 0 —— 决策与合规前置（2–4 周）**
- 出 ADR：强管制版独立产品线、双 flavor 工程、ADB 预置通道决策、逃生舱设计。
- 合规清单：未成年人模式对齐、隐私政策修订、App 备案路径、PIPL 监护人同意流程。
- 选定 POC 机型 2–3 款（如某品牌学习平板/教育平板 + 当贝类盒子）。

**阶段 1 —— Android MVP（单家庭多设备，6–10 周）**
- 儿童守护端：DPC 合一包、ADB 预置、DO 策略中心、Lock Task 动态进出、静默更新、逃生舱、策略重放。
- Web：家庭设备台账/策略版本/命令队列/报告聚合/下载中心双 APK。
- 通道：P2P 长连接 + HTTP 轮询兜底。
- 验证：AVD `dpm set-device-owner`（可行）+ 2 款真机；安全基线回归。

**阶段 2 —— 家庭规模化（8–12 周）**
- 家庭多设备、分组策略（多娃）、审计导出、OEM 预装渠道评估。
- Android TV flavor（leanback/遥控导航）+ GMS 设备二维码通道。

**阶段 3 —— 扩展端（按需）**
- iOS 家庭 iPad 手工监督评估（可选）；鸿蒙 NEXT 原生版评估；Windows 仅家长端增强（微软家庭安全集成/Assigned Access 指引）。

### 5.2 中国大陆适配性

1. **无 GMS 是最大结构性约束**：QR/NFC/zero-touch 批量预置全部依赖 Google Play 服务；国产设备上强管制版预置通道实际只剩 ADB 与 OEM 预装。**ADB 预置已升级为「无线调试自授权」通道（ADR 0018，无需电脑，LADB 模式）**：内嵌官方 adb 二进制 + 6 位配对码自配对 + `dpm set-device-owner`，2026-08-24 实测 OPPO PKV110（Android 16）自配对成功、AVD Android 14 dpm 成功、华为 FRD-AL10（Android 8）低版本拦截。
2. **OEM 限制**：OPPO/小米等对第三方 `dpm` 预置有额外校验（需无账号/初始状态），且内置儿童空间/学生模式功能重叠；建议先做厂商白名单机型，或走 OEM 合作预装（家长专用设备渠道）。
3. **ROM 碎片化**：锁任务、保活、无障碍行为差异大，必须机型矩阵测试（本项目 OPPO 真机缺陷史是前车之鉴）。
4. **鸿蒙 NEXT**：不兼容 APK，覆盖需原生开发，暂缓。
5. **网络与备案**：国内服务器/域名 ICP 备案（xpc.winann.com 已有经验）、app 备案、公安备案；P2P 中继防滥用沿用 K3 限速等既有能力；HTTPS 优先。
6. **分发**：自建下载中心可行；上应用商店需声明敏感权限（设备管理器/无障碍/用量）用途并过审，强管制类目审核从严。
7. **内容生态**：学习内容（课程/视频）需内容合作与合规（教育内容资质、播控牌照边界），纯管控工具可先不做内容。

### 5.3 合规问题

| 法规/文件 | 对本产品的要求 | 落地动作 |
|---|---|---|
| 《未成年人网络保护条例》（2024-01-01） | 未成年人模式、监护人同意、个人信息保护、防沉迷、便利未成年人行使权利 | 强管制版主动对齐「未成年人模式」入口；家长可设限额；儿童可求助/紧急呼叫 |
| 《个人信息保护法》第 28–31 条 | 不满 14 周岁个人信息 = 敏感个人信息，需监护人单独同意；最小必要；删除权 | 首次启用强管制需家长账号验证（邮箱+验证码）+ 单独同意留痕；数据仅存必要字段；提供导出与删除 |
| 《儿童个人信息网络保护规定》（网信办 2019） | 委托处理、访问控制、安全事件报告 | 数据处理协议、权限矩阵、安全事件流程（家长-平台间） |
| 《数据安全法》《网络安全法》 | 分类分级、日志留存、网络安全责任 | 消费者级应用以安全基线+运维为主；数据不出境（本地化部署=合规加分）；若上应用商店按商店与监管要求 |
| 《移动互联网应用程序信息服务管理规定》+ App 备案 | 应用备案、信息内容安全责任 | 上架前完成 app 备案；隐私政策/权限声明 |
| 《移动互联网未成年人模式建设指南》（网信办） | 统一未成年人模式入口、时长限制、适龄提示、防绕过 | 产品按指南实现（时长、内容分级、家长验证、不可诱导脱离模式） |
| 广电 OTT 播控（TV 场景） | 互联网电视内容需牌照方播控 | kiosk 不做内容聚合；预置内容由合规内容方提供 |
| 方案修订边界（用户约束 v1.1） | 不涉及学校/机构；不采集真实姓名、证件、通讯录 | 家长身份验证 = 邮箱+验证码+首次设备绑定，不用证件；儿童侧零姓名/证件/通讯录采集；与既有 R6.4（禁通讯录/短信/位置）一致 |

**底线（不可妥协）**：
- 透明告知：设备被强管制的事实、采集范围、数据去向必须明示。
- 可退出：家长受控退出通道 + 儿童求助通道必须存在。
- 不隐蔽监控：禁止伪装、隐蔽采集、无提示接管——这是工信部 App 治理与商店审核的红线，也是 stalkerware 类产品的翻车点。
- 不宣称「绝对锁定」：如实说明安全模式/Recovery/ADB 等残余绕过向量。
- 身份策略：家长身份验证 = 邮箱 + 验证码 + 首次设备绑定，不依赖证件；儿童侧不采集姓名/证件/通讯录，敏感数据面最小。

## 6. 其它问题与同类应用教训

### 6.1 绕过向量与对策（如实标注可行/不可行）

| 绕过方式 | 强管制版能否防 | 说明/对策 |
|---|---|---|
| 设置中关闭设备管理器/DO | 不能（DO 应用不可卸载，但策略变更需应用侧同意） | 逃生舱需家长验证；DO 下用户强停按钮禁用 |
| 强制停止 | DO 应用用户不可强停 | 结构性解决 |
| 卸载 | 不能（DO 禁卸载） | 结构性解决 |
| 安全模式启动 | 不能 | DO 应用不加载；下次正常启动检测并告警 |
| Recovery 恢复出厂 | 多数 ROM 不能 | 第三方 DO 拦不住硬恢复；FRP 依赖厂商账号体系，如实告知 |
| ADB/root/Xposed | 部分（可禁 USB 调试，防不住 root 设备） | 禁调试 + 检测 root；root 设备不做强管制承诺 |
| 多用户/访客/分身 | 部分（DISALLOW_ADD_USER/DISALLOW_USER_SWITCH；分身包名需白名单覆盖） | 机型矩阵实测 |
| 时间篡改 | 可防（DO 强制自动时间 + 服务端时间校准 + 审计） | 超时判定以服务端时间为主 |
| 关机/断网 | 不能 | 重启后策略重放（boot receiver + enforcement 标记）；断网期间本地兜底 |
| 第二台设备/热点 | 不能 | 明确能力边界：只管控本设备 |
| 固件更新重置策略 | 部分 | 更新后策略重放；OTA 后回归矩阵 |

### 6.2 运维与生命周期问题

- **设备回收/转卖**：必须支持受控解除 DO（否则二手设备被锁死）；流程 = 管理员验证 → `clearDeviceOwnerApp`。
- **孩子成长退出**：数据导出、解除管控、恢复普通机的一键流程。
- **售后客服**：儿童误锁、家长忘记密码、远程解锁请求 → 需客服/工单；这是纯软件项目最容易低估的成本。
- **设备丢失/损坏**：远程擦除（DO wipe）、设备台账标记、补发预置。
- **版本兼容**：DPC 与 kiosk 同签名、升级兼容测试；K3 限速等既有问题（SEC 基线）在设备量增大后更关键。

### 6.3 同类应用分类与教训

| 类型 | 代表 | 教训 |
|---|---|---|
| 无障碍+用量系（家庭） | 格雷盒子、麦苗守护、阳光守护等 | 被绕过/权限被撤销问题多；商店对无障碍/设备管理器审核敏感；隐私投诉高发 |
| OEM 内置系 | OPPO 儿童空间、小米儿童空间、华为学生模式、鸿蒙儿童模式 | 系统级最强，但封闭、内容生态绑定；第三方 kiosk 与之正面竞争处于劣势 → 差异化在统一多设备管理+报告+家庭联动 |
| 学习平板系（家庭购买） | 步步高、读书郎、优学派、小天才 | 硬件+系统+内容一体化；纯软件需靠 OEM 合作或自带内容生态 |
| 国际 MDM/kiosk | Esper、Hexnode、SureLock、Family Link | 依赖 GMS/企业渠道，中国大陆不可直接复制 |

### 6.4 常见翻车点（对照自查）

1. 宣传「绝对锁定/无法绕过」→ 虚假宣传与投诉。
2. 敏感权限（设备管理器/无障碍/用量）未在隐私政策明示、未过商店审核 → 拒审/下架。
3. 后台留存儿童行为数据过细（屏幕内容/位置/通讯录）→ PIPL 违规 + 舆情。
4. 只做软件不做硬件/OEM → 被系统内置儿童模式替代。
5. 单一 ROM 适配即上线 → 机型兼容事故（本项目 OPPO 前科）。
6. 无逃生舱 → 家长锁死设备后的售后灾难。
7. 数据越界采集（姓名/证件/通讯录）→ 合规与舆情事故；务必保持最小化。
8. 开源免费定位与商业化张力 → 建议家庭版免费 + 强管制版订阅/一次性授权双轨。

## 7. 结论与建议

### 7.1 做 / 不做 / 优先级

- **做**：Android 家庭专用平板/盒子的强管制版（阶段 1 MVP，ADB 预置 + 家庭多设备 + 双 flavor 工程）；后端做轻量家庭设备管理面；合规先行。
- **暂缓/不做**：iOS 家庭 iPhone 强管制（不可行）、Windows 儿童端强管制（收益低）、鸿蒙 NEXT（另算工程量）。
- **可选**：Android TV flavor（阶段 2）、GMS 设备二维码通道（阶段 2）、iOS 家庭 iPad 手工监督（长期可选）。

### 7.2 立即下一步（评估后建议，未执行）

1. 新增 ADR：强管制版产品线界定、双 flavor 工程、ADB 预置通道、逃生舱设计。
   **已完成**：ADR 0018（自授权预置通道，v1.3.0 交付并三端实测）；逃生舱（受控解除 DO）与
   双 flavor/kiosk 策略中心划入 V2。
2. 出合规清单与隐私政策修订草案（未成年人模式对齐、监护人同意、App 备案路径）。
3. 选定 2–3 款 POC 机型并验证 `dpm set-device-owner` 可行性（OPPO/联想/当贝等）。
4. Web 后端 schema 草案：org/group/device/policy/consent/command 表与接口清单。
