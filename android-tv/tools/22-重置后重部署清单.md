## 0. 结论先行（重置前已知，重置后要复核）

`.22` 拿不到 device owner 的原因在 **`/system` 分区**（只读），恢复出厂只格式化
`/data` 与 `/cache`，**改不了 `/system`** ⇒ 预期重置后仍然拿不到。

两条门槛分属不同分区：

| 门槛 | 位置 | 恢复出厂能否解决 |
|---|---|---|
| ① device policy 框架是否声明（`android.software.device_admin`）| `/system/etc/permissions/*.xml`，**只读** | ❌ 不能 |
| ② 设备是否"已初始化完成"（`USER_SETUP_COMPLETE`）| `/data` | ✅ 能（但"三步插队"本就能等效绕过，无需重置）|

## 1. 重置后第一件事：让 adb 能连上（最容易卡在这里）

新系统 **ADB 默认关闭**，且 IP 可能变（DHCP）。

1. 过开机向导 → 设置 → 关于 → 连续点「版本号」7 次，开启开发者选项
2. 开发者选项 → 打开 **「网络调试」**（注意：只开「ADB 调试(USB)」不会监听 5555）
3. 记下新 IP，然后：
   ```bash
   ping -c2 <新IP>                      # 网络层
   nc -z -G2 <新IP> 5555                # 端口层（refused = 开关没生效）
   adb connect <新IP>:5555
   ```
   连不上时的分层排查见 `android-tv-development` 技能 §15（全端口扫描判"端口变了 vs daemon 没绑定"）。

## 2. 连上后立刻做的决定性判定

```bash
adb -s <dev> shell pm list features | grep -i device_admin     # 空 ⇒ 框架仍缺失
adb -s <dev> shell "ls /system/etc/permissions/ | grep device" # 空 ⇒ 无声明文件
adb -s <dev> shell "grep -rl software.device_admin /system/etc/permissions/"
adb -s <dev> shell mount | grep ' /system'                     # ro ⇒ 重置改不了
adb -s <dev> shell "su -c id"                                  # su: not found ⇒ 无 root
```

**预期结果：全空 ⇒ 证实"恢复出厂对 DO 无效"**，可直接收工，不必再试 `dpm`。

## 3. 万一框架存在（大概率不会）→ 三步插队拿 DO

```bash
U=$(adb shell settings get secure user_setup_complete | tr -d '\r')
D=$(adb shell settings get global device_provisioned  | tr -d '\r')
adb shell settings put secure user_setup_complete 0     # 制造"未初始化"窗口
adb shell settings put global device_provisioned 0
adb shell dpm set-device-owner com.xiaopacai.tvos.debug/com.xiaopacai.tvos.service.GuardianDeviceAdminReceiver
adb shell settings put secure user_setup_complete ${U:-1}   # 必须还原
adb shell settings put global device_provisioned  ${D:-1}
```

一键脚本（含前置检查 + trap 还原 + 四重验证）：
`~/.hermes/skills/software-development/android-device-owner/scripts/set-device-owner.sh`
⚠️ 重置后是"未初始化"状态，理论上第 ① 层若活着可直接 `dpm set-device-owner`（无需插队）。
⚠️ 前置条件：**账号数必须为 0**（`dumpsys account | grep -c "Account {"`）。
