# ADR 0016 — V1.1.1 加固：四项真机缺陷的架构裁决

- 日期：2026-08-15
- 状态：已采纳（TASK-HARDENING-V1.1.1）
- 范围：Android 儿童端/家长端 + Web 服务端（Bug1 上滑管控失效 / Bug2 倒计时不更新 / Bug3 日志不上传 / Bug4 无障碍权限丢失）
- 依据：140 信 + PROMPT_MILESTONE_V1_1_1.md（所有决策项已由产品负责人确认，执行期间不再询问）

## 背景

V1.1.0 在 OPPO 真机回归中发现 4 个 P0 缺陷：上滑结束小趴菜后管控失效、儿童端倒计时
不更新、日志未上传且 Web 查日志报错、无障碍权限丢失后无感知。本轮逐项修复并交付，
涉及多条跨进程/跨端链路，特记录以下架构裁决。

## 裁决（按红线 安全 > 功能 > 性能）

### ADR-0016-1 失守监控链路：本地优先 + P2P 直传 + 云端转传（Bug1-D）

儿童端 GuardDownMonitor 本地持久化失守事件（cap 100），P2P 优先直传家长端
（guard_event + 健康度快照），离线入队由 SyncManager 冲刷；家长端本地落盘 +
高优通知（id 4001）+ 异步转传 Web（POST /api/guard-events）。

- 为什么：P2P 直传保证家长端「实时」看到失守（无云中转延迟）；云端转传保证
  Web 历史可查与跨设备可见；本地持久化保证离线不丢。
- 恢复判定按 reason 匹配结算（pendingReason），避免「无障碍检查周期恰好关闭
  process_killed 事件」的错误结算。
- 未采用：只走云端单通道（丢失实时性）、内存态不持久化（进程被杀即丢）。

### ADR-0016-2 秒级倒计时：交互增量 + 失效如实展示（Bug2）

剩余 = 今日限额 −（最近采集已用 + 距最近采集的交互增量）。增量**仅在屏幕交互
（isInteractive）时累计**，熄屏不计（与 UsageStats 口径一致）。

- 与需求文字「距最近采集时间增量」的差异：需求未指明熄屏处理；若按墙钟累计，
  夜间熄屏会虚减倒计时，儿童早上起来「凭空少几小时」，违背数据真实性红线。
  故裁决为交互增量，并在 60s 采集锚点下增量上限 ≤60s。
- 归零立即锁定：UI 每秒 tick 调 lockIfCountdownExpired 走 TimeoutExecutor 锁定，
  与 60s 采集判定构成双保险（消除 ≤60s 空窗）；失效时不虚构锁定。
- 权限撤销/采集异常/超 3 周期未成功 → 「守护失效」如实展示（禁止假倒计时），
  附恢复引导文案。

### ADR-0016-3 无障碍丢失：事件+定时双触发，仅检测引导不自动重开（Bug4-A）

亮屏/解锁（动态注册，守护前台服务常驻）+ 应用更新（MY_PACKAGE_REPLACED 静态
兜底）+ 回前台（Application 回调）立即自检，30 秒节流；每分钟轮询兜底保留。
发现被关立即高优通知 + 一键直达无障碍设置。

- 边界（平台硬限制）：第三方应用无法自动重新开启无障碍服务，只能检测 + 引导 +
  告警；被强制停止的应用无法自恢复。文案如实区分「管控曾生效=拦截已失效」/
  「未生效=守护受影响」，不夸大。
- 未采用：后台高频轮询（耗电）、尝试重启无障碍进程（无效且有规避系统之嫌）。

### ADR-0016-4 Device Owner 仅检测展示，不落地 DPC 激活（Bug1-C）

只检测（isDeviceOwnerApp/isProvisioningAllowed）并展示于健康度，不发起任何
预置流程、不引导 ADB（与既有「普通用户界面不出现 ADB/命令」决策一致）。
Device Owner 不参与 0-100 健康度评分（信息项），避免误导。详见 docs/DEVICE_OWNER.md。

### ADR-0016-5 app_logs 表名映射修复 + 真实 SQLite 回归防线（Bug3-A）

根因：EF 默认按 DbSet 属性名查 AppLogEntries 表，DataExtensions 建表 DDL 为
app_logs → 查询 "no such table" 500；此前测试用 InMemory 提供程序不校验真实
表名故未拦截。修复：OnModelCreating 显式 ToTable("app_logs")（存量库零迁移）；
防线：新增真实 SQLite 表名一致性回归测试（存量库 DDL 路径 + EnsureCreated
新库路径），并推广至 guard_events（建表即显式 ToTable）。

### ADR-0016-6 上传退避：5/15/60 分钟指数退避 + 6 小时兜底（Bug3-B）

登录/绑定成功立即上传；失败持久化原因 + 一次性退避任务（第 1 次 5 分钟、
第 2 次 15 分钟、其后 60 分钟，REPLACE 幂等，成功清零并取消）；原 6 小时
WorkManager 周期任务兜底保留。日志页如实展示上次成功时间/失败原因/重试计划
（成功即自动消失）。未采用 WorkManager 自带线性退避（分钟粒度不可控、上限低）。
